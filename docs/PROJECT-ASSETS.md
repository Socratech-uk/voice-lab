# Project workflow

Foundry 0.1.0 · 3D Lab 0.14.0 · Voice Lab 1.9.0 · Kestrel 0.36.0

## A project is a folder

Choose the full Kestrel checkout. The source-only upload does not contain the
original mesh/audio bytes. Foundry scans what is present, reports missing files,
and can recover them with **Sync project files** after the full files are available.
It retains originals, creates immutable project copies, and preserves assignments.

Each folder has its own `workspaces/assets/registry.json`, file store and history.
You can open eight projects and switch between them; recent folders are remembered.
Two copies of Kestrel with the same project ID remain separate sessions. This is
local synchronization between apps attached to one folder, not cloud folder merging.
Do not run two folder services on the same checkout. If Open-Asset-Workspace is
already running, use its Foundry window/link or close it before opening that folder
from another Foundry service.

The same stable asset ID has independent **Model**, **Movement** and **Sound**
assignments. Upgrading art changes its assigned revision, preserving save/inventory
identities. New IDs can be used as attachments; creating an ID does not automatically
spawn it in a level. Assigning models does not alter collision or equipment ownership.

## Model and movement

Import self-contained GLB up to 64 MiB. Saved Action Lab GLBs include their recipe;
Foundry extracts it and keeps it with the revision. For skeletal characters, Model
and Movement must use the same saved revision, with a reviewed rig and idle plus
walk/run movement slots. Foundry previews exported actions; Action Lab remains the
full motion/retargeting/foot-contact authoring tool.

Use **Edit in Action Lab / 3D Lab** for a copy of the chosen revision. Save a new
draft in that editor, then **Project Assets → Copy selected draft to project**.
Assign it back to the same asset ID and publish. Installed apps need the project
connection link; browser editors receive it automatically. A browser editor does
not borrow the installed lab's AI engine. Original recordings and models remain.

## Assemblies

In Assembly, **Place socket on model** shows a surface cursor. Click to place it;
Escape cancels. Choose a joint to make the socket move with a weighted character.
Socket transforms use the model's root coordinates in the resting pose, rather
than a second guessed bone-local offset. An attachment's transform is relative to
its socket. Choose another project asset, attach it, then move, rotate or scale it.
Numeric fields, duplicate, visibility, reset, undo/redo and recipe import/export
are available. F fits; G moves; R rotates; S scales. Ctrl+S saves; Ctrl+Z undoes
assembly changes; Ctrl+Shift+Z redoes. The viewport supports fullscreen and PNG capture.

Up to 32 sockets and 64 direct attachments per asset, eight nested levels and 256
instances per assembled object. Cycles, missing IDs and stale joint references are
rejected. Model replacement must preserve assigned joint IDs or you must remap the
sockets first. The browser preview has a 2.5-million-vertex budget.

Kestrel draws static attachment meshes through its normal material renderer, under
root sockets or the current skin deformation. A character may be the assembly base;
attached children must be static models. Existing rigid character/weapon paths have
root attachment hooks. Bone sockets require weighted Action Lab characters; legacy
named-part rigs are not silently mapped to skeletal joints. Distant infantry proxies
omit attachments. New physics bodies, gameplay weapon mounts, vehicle interiors and
equipment ownership are not generated by a visual assembly.

## Sound

Import PCM WAV up to 64 MiB, or edit a project recording in Voice Lab and copy the
saved revision back. Each event supports 1–8 variations, volume, pitch range,
reference/max distance, cooldown, voice limits, spatial playback, fades and a mixer
bus. Changes to multiple events stay in the draft until **Save edits** commits them
together with asset details and assembly. Mixer levels have their own Save button.

| Event | Kestrel source hook |
| --- | --- |
| `footstep` | Character foot-down action markers, contact-window starts, or distance-based fallback on legacy/unmarked characters |
| `jump`, `land` | Character grounded-state transitions |
| `fire` | Accepted hand-weapon shots and player ship weapon shot counters |
| `reload`, `reload-end` | Hand-weapon reload state; ship reload timers do not emit these yet |
| `impact`, `death` | Hand-weapon actor hits and ship damage outcomes |
| `engine` | Player ship power/engine state, with thrust gain |
| `door-open`, `door-close` | Player cargo ramp changes; not every world door |
| `idle` | Reviewed character idle state |
| Other names / `voice` | Exact action event markers; dialogue selection is still gameplay-owned |

An exact foot marker binding wins; otherwise `left-foot-down` and similar names
fall back to `footstep`. A contact start creates that foot's down cue if no explicit
cue for that foot was authored. No foot IK is added. First-person body movement uses
state/distance fallback while the full body is not rendered. Named skeletal cues
play on visible weighted characters; manually placing events does not itself alter
gameplay state or cause a projectile to fire.

Engine/idle loops follow their active state. Other looping events need an exact
`event-name:stop` marker; changing scene or pausing stops all game emitters. Keep
one-shot effects non-looping. Native audio is bounded to 48 streaming voices, with
per-event/instance limits, and does not change the local AI owner's master volume.
The browser preview caps voices at 32 and its decoded buffer cache at 128 MiB.
**Preview saved event** auditions at the listener; animated cues use preview-camera
distance/pan. **Stop sounds** stops browser playback.

The movement playtest is a simple assembly preview: WASD move, Shift run, Q/E turn.
It is not a reproduction of Kestrel physics, collisions or the full Action Lab game
controller. Review starts/stops, stance, air and head/arm controls in Action Lab;
then accept the result in the real game once native validation is permitted.

## Save, check, publish and recover

Save edits commits the entire asset atomically after validation. Concurrent edits
use expected project/revision checks; stale writes fail. If another lab changes the
project while you have unsaved edits, use Refresh to discard and review those edits.
Otherwise connected windows poll and refresh automatically. History restores earlier
assignments, details, assemblies, sound settings and mix; new files and IDs are kept.

Check validates/cooks in memory without changing runtime files. Publish records
`assets/project-bindings.json` plus immutable files under `assets/project-library/`.
A failed publication retains the prior authoritative manifest. Original definitions,
mesh bytes and sources stay intact. Rebuild/restart Kestrel after publication.

Foundry binds only to loopback, uses a private per-launch connection token and opaque
per-folder session keys, checks origins/Host, and grants no general file read/execute
API. Folder grants reject path escapes, symlinks and junctions for managed files.
Keep connection links private. No network download or AI install is needed at runtime.
